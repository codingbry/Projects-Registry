# Omarchy Multi-User Hyprland Configuration Guide: Deploying `end-4` (`illogical-impulse`) for Secondary Accounts

**Category:** Omarchy / Linux System Administration  
**Status:** **Resolved & Stable**  
**Target Environment:** Omarchy (Arch Linux-based Hyprland Distribution)  

---

## 1. Overview & Objectives

When sharing an Omarchy system with secondary users (e.g., family members or guests), maintaining personal desktop configurations ("rice"), application states, and file security is critical. Because Linux manages user privileges and configuration environments at the `/home/$USER` level, distinct desktop environments and dotfile ecosystems can coexist seamlessly on the same underlying operating system without polluting or modifying the primary administrator's desktop setup.

This technical log documents the step-by-step setup and deployment of the **`end-4` (`illogical-impulse`)** Hyprland configuration suite for a secondary user account (`nininjoy`) on an **Omarchy** host system, while preserving the primary user account (`pumpkin`) configuration.

---

## 2. Technical Challenges & Root-Cause Analysis

During the deployment process, several execution hurdles unique to Omarchy's system architecture were encountered:

### Issue A: Default Fallback to Global Omarchy Configs
* **Symptom:** Logging into a newly created standard user account launched the default system-wide Omarchy Hyprland setup rather than a fresh or customized desktop environment.
* **Root Cause:** Hyprland defaults to reading `/etc/hypr/hyprland.conf` if user-level configuration files do not exist inside `~/.config/hypr/hyprland.conf`. On Omarchy, `/etc/hypr/hyprland.conf` imports global Omarchy shell and keybinding scripts.

### Issue B: Directory Structure Mismatch in Installer Execution
* **Symptom:** Executing `./install.sh` or standard python setup commands resulted in `No such file or directory` errors (`Errno 2`).
* **Root Cause:** The `end-4/dots-hyprland` repository structures configuration templates inside a `./dots` subdirectory and relies on a top-level executable entry point (`./setup`) with specific subcommands (`./setup install`).

### Issue C: Omarchy System Protection Interceptions (Pacman Hooks)
* **Symptom:** Running the `./setup install` workflow resulted in transaction failure:
  ```text
  error: command failed to execute correctly
  error: failed to commit transaction (failed to run transaction hooks)
  ```
* **Root Cause:** Omarchy implements system safety hooks preventing raw `pacman -Syu` invocations. The installer script's default package upgrade step triggered Omarchy's update interceptor.

## 3. Step-by-Step Resolution & Implementation Log

### Step 1: User Account Creation & Privilege Provisioning
1. From the primary administrator account (`pumpkin`), create the secondary user account and assign initial group privileges:
   ```bash
   sudo useradd -m -G wheel -s /bin/bash nininjoy
   sudo passwd nininjoy
   ```
2. Grant temporary elevation privileges to permit installer setup (or allow execution via PAM/sudoer policy):
   ```bash
   sudo usermod -aG wheel nininjoy
   ```

### Step 2: Session Isolation & Dotfiles Repository Cloning
1. Switch to the target user account via a clean login shell to load updated group permissions:
   ```bash
   su - nininjoy
   ```
2. Clone the `end-4/dots-hyprland` configuration repository into the target user's local config path:
   ```bash
   git clone --depth 1 https://github.com/end-4/dots-hyprland.git ~/.config/end-4-dots
   cd ~/.config/end-4-dots
   ```

### Step 3: Executing the Setup Pipeline & Handling Omarchy Hooks
1. Execute the primary end-4 installer script from the secondary user environment:
   ```bash
   ./setup install
   ```
2. When prompted with the `pacman -Syu` error generated by Omarchy's transaction hooks, choose **Option A** or **Option B**:
   * **Option A (Recommended):** Press `i` to **Ignore** system package upgrades. Since Omarchy already installs base dependencies (Hyprland, Waybar/AGS, Quickshell, Python, dependencies) system-wide, package installation can be safely bypassed.
   * **Option B (Direct Bypass):** Exit the prompt and execute the installer with Omarchy's override variable:
     ```bash
     OMARCHY_ALLOW_DIRECT_PACMAN=1 ./setup install
     ```
3. Alternatively, bypass privileged scripts entirely and deploy configuration dotfiles directly:
   ```bash
   cd ~/.config/end-4-dots
   ./setup install-files
   ```

## 4. Verification & Desktop Launch Rules

1. Log out of all active sessions or switch to the primary display manager (SDDM/GDM/TUIGREET).
2. Select the secondary user account (`nininjoy`).
3. **CRITICAL:** Ensure the session type selected in the display manager is **`Hyprland`** (Standard Session) and **NOT** `Hyprland (uwsm)`.
4. Log into the account.

### Operational Verification
* **Wallpaper Selector:** Press `Ctrl` + `Super` + `T` to confirm Quickshell/AGS widget responsiveness.
* **Keybind Reference Sheet:** Press `Super` + `/` to open the `end-4` keybindings overlay.
* **Isolation Verification:** Logging back into `pumpkin` confirms all Omarchy system keybindings, bar configs, and scripts remain unaltered.

---

## 5. Summary & Project Index Update

By directing user-specific configurations to `/home/nininjoy/.config/hypr/` and `/home/nininjoy/.config/ags/`, multi-tenant desktop customization is achieved on Omarchy without modifying root partition defaults.
